# Glossary

One entry per name. A name links to the reference page that describes it, where one does.

| Name | What it is |
|---|---|
| **[thread](thread.md)** | The append-only list of lines of one record. Read in **reading order**: by the chain: from the line with no `previous`, each next line the one that names the last. |
| **[line](thread.md#types)** | One entry: `id`, `previous`, `gist`, `writer`, `timestamp`, `payload`, and on a thread's first line only its **declaration**, `thread`. The payload is free JSON. |
| **[declaration](thread.md#the-declaration)** | What a thread's first line says of the thread, in its `thread` field: a nonce, a random value used once (16 bytes in lowercase hex, drawn by `stamp` or handed to it), and the schema's `name` and `version` when it has them. A consolidation's first line also carries `from`, its **seals**. It is in the line's hash. A thread declared for another schema is refused whole; a first line with no `thread` declares nothing. |
| **[id](thread.md#stamp)** | What names a line: `sha256:` and then the SHA-256 of the line's content and its `previous` id, in RFC 8785's form, computed once when the line is written and stored. The id names its recipe: `verify` reads the name before it checks, and refuses one it does not know. |
| **[gist](schema.md#gist-schemas)** | What a line says happened: `memo`, `doc_signed`, `bank_tr_complete`. Lower snake case, at most 32 characters. |
| **[writer](thread.md#writers-and-strings)** | Who wrote a line, as `KIN::ID`: `user::mrossi`, `system::bridge`, `goal::<line id>`. |
| **[kin](thread.md#writers-and-strings)** | The part of a writer before `::`. A gist's schema says which kins may write it. |
| **[schema](schema.md)** | A domain, as data: a head, its gist schemas, its laws. Read once by `readSchema` against a kit. |
| **[head](schema.md#the-head)** | The part of a schema that names its own words: its `name` and `version`, both or neither, the `opening` gist, the `authority`, the `sets`, the `records`, the kins `judged`, the named `guards`. |
| **[authority](schema.md#the-head)** | The writer of the lines that record a reconciliation, named by the head. In SIBAR, `system::sibardoc`. |
| **[gist schema](schema.md#gist-schemas)** | One gist's configuration: its writers, its `when`, its rule bindings. |
| **[opening gist](schema.md#the-head)** | The gist a thread starts with; exactly one is in force. In SIBAR, `create`. |
| **[rule](schema.md#rule-bindings)** | A registered kind of consequence, bound to a gist by a **binding** that names the payload keys it reads. A rule states expectations; it never compares. |
| **[mechanic](schema.md#rule-bindings)** | What belongs to the thread itself and is not a kind: the envelope and its hash, reading order, **revoke**, **goal**, the opening rule, `when`, the loop and bound of reconciliation, the place of laws in a post. The engine reads them; a kit cannot replace them. |
| **[rule kind](schema.md#rule-kinds)** | The code behind a rule: how its binding is read, why a payload cannot carry it, what it expects, and into which handle kinds. |
| **[revoke](schema.md#revoke)** | The rule that takes a line out of force. Always specific: a revoking gist lists the gists it may revoke. |
| **[in force](reading.md#in-force)** | Not revoked by a line that is itself in force. |
| **[handles](reading.md#types)** | The values on the record that the thread explains, outside the thread so they can be listed and searched. |
| **[handle kind](schema.md#handle-kinds)** | The code behind a sort of handle: its empty form, how expectations of it are compared with it, how a denunciation of it is answered, how two of its handles differ, and the roles of the records it writes. Two ship with the library: |
| **[value handle](schema.md#handle-kinds)** | A handle that holds one JSON value under a key. In SIBAR, a metadata key. |
| **[set handle](schema.md#handle-kinds)** | A handle that holds a set of names. In SIBAR, the assignees. |
| **[kit](schema.md#the-kit)** | The handle, rule and law kinds a schema may use. `BASE_KIT` ships with the library (its rules: `value`, `collect-writer`, `join`, `leave`); a schema is read against one, and refuses a kind it lacks. |
| **[join](schema.md#join-and-leave)**, **[leave](schema.md#join-and-leave)** | The rules that put names into a set handle, and take the writer out of one. In SIBAR, assign and release. |
| **[expectation](reading.md#expectations)** | What the thread says a handle should be, or that a line should exist. |
| **[reading](reading.md)** | What follows from a thread, against its handles: lines in force, expectations, goals, denunciations, holes. `consequitur(lines, handles, schema)` gives it; the word names the act too. |
| **[denunciation](reading.md#denunciations)** | One difference between an expectation and the handles (`sort: 'handle'`), a line a goal owes (`'line'`), or a breach of the opening rule (`'thread'`). |
| **[change](posting.md#diff)** | One difference between two handles, as its handle kind says it, for a host to apply to its own copy. `diff` lists them. Between two readings, a change is what `changes` lists: a line's standing, a goal, a check, a denunciation, a hole opened or filled, the thread's settling, each with a key (from `keyOf` or `keyOfCheck` where the reading gives none). |
| **[reconciliation](posting.md#settle)** | The answer to a denunciation: the handles change and a line records it. Settling repeats it until nothing is left to answer, one goal's outcome per round in thread order, within a bound the goals give. |
| **[record](schema.md#the-head)** | A line the authority writes to say a reconciliation changed a handle. Each has a **role** (`value`, `join`, `leave`, or one of a kit's own), and the head's `records` names the gist of each role, and of the goal's `warning`. |
| **[goal](reading.md#goals)** | A line that names a condition, its `when`, and an outcome. When the condition holds, the goal writes its outcome, once; goals met in one reading write theirs one per round, in thread order. |
| **[check](conditions.md#where-a-line-node-looks)** | An equality on a line's gist, kin, writer and payload keys: what a `line` node of a condition asks of the lines in force. A payload value in it may be a `$value` reference. |
| **[condition](conditions.md)** | What a `when`, a goal and a law's `while` say: kdlet's guards, `is`, `has`, the four **comparisons**, `not`, `all`, `any` and a named **guard**, with the two **words** consequitur registers, written as JSON with **references**. It holds or it does not; only the draft a menu is drawn for, and the instant nobody gave, are unknown. |
| **[comparison](conditions.md#comparisons)** | One of the module's four words of order, each between two operands, the left first, all strict: `before` and `after` compare times (an RFC 3339 date, or an instant with its offset, never one against the other), with `days` to move the right date by whole days; `less` and `more` compare JSON numbers. What does not compare is false. |
| **[guard](conditions.md#named-guards)** | A condition the schema's head names, used by `{ "guard": name }` in a `when`, a goal or a law. |
| **[word](conditions.md#nodes)** | A node of a condition that consequitur registers on `kdlet-guards`: `line` (a line in force matches a check) and `at-least` (a quorum of its children). |
| **[trace](conditions.md#the-trace)** | What reading a condition found, node by node: whether each holds, on a `line` node the line that met it and the check as matched, and, where warnings are, whether it cannot hold. A goal's reading carries it. A node's path, its indexes from the root joined by dots, is its key. |
| **[outcome](reading.md#goals)** | The line a goal writes, with the payload the goal carries. |
| **[final](reading.md#goals)** | A goal whose outcome can never be revoked. |
| **[warning](reading.md#goals)** | The line a goal writes, `{ path }`, when its condition cannot hold, once for each path: `path` names the node that made it so (a `line` node whose check names what the thread lost, or an `any` or `atLeast` with too few children left). |
| **[when](offers.md)** | When a gist may be written: a condition, read with the writer, the draft and the instant the line is admitted at (`$now`). What the menu is built from: there the draft and the instant are unknown, and a gist is offered unless its `when` is false. |
| **[offer](offers.md)** | A gist a writer may write on the thread as it stands, with the lines it may name if it revokes. |
| **[law](schema.md#law-bindings)** | A registered judgement on what a line would cause, with a strength: refuse, or confirm. The schema binds it, and its head says whose lines are `judged`. `keeps-set`'s `while` is a condition. |
| **[verdict](posting.md#laws-and-verdicts)** | One law found broken by a dry run. |
| **[dry run](posting.md#dryrun)** | A post whose result is kept and not applied: the lines it would add, the rounds, the verdicts. |
| **[refusal](posting.md#refusal-codes)** | The answer when a line cannot join a thread: a `code`, a sentence in `detail` for a developer, and, for a law, its `verdicts`. A refusal leaves the thread as it was. |
| **[policy](posting.md#the-policy)** | Which denunciations an authority leaves unanswered, each entry with optional values the value handle must hold for it (`while`). Configuration, outside the thread. A reading that only the policy keeps from settling counts as settled. |
| **[render](render.md)** | `consequitur-render`: helpers that turn a reading into DOM, owning no markup: each line's facts, nodes kept by line id, the dry-run preview loop, the **band** (the line drawn from a slot to a line, or between two elements). |
| **playground** | The sample application: a domain's thread written by hand, its reading inspected, its schema shown as code. It runs one domain at a time and has a picker for them. |
| **case** | A domain's files in `cases/<domain>/`: its schema, its scenarios and, where it has one, its policy. The tests and the playground read the same files. |
| **[scenario](scenarios.md)** | A domain's story as data: a list of **steps**, posted one after the other to an empty thread, each through admission. Played by `playScenario`, from the package; `prune` and `stepsOf` save one from a thread, `replayed` and `stepsOf` replay one in a consolidation, and `holed` makes the values an application names into holes. A scenario saved so, and with holes, is what an application's users call a template. |
| **[step](scenarios.md#types)** | One line of a scenario: `{ writer, gist, payload }`, with a `label` if a later step points at the line it posts, `confirmed` if a `confirm` law asks it, `refused` if the scenario expects the engine to refuse it. |
| **[placeholder](scenarios.md#placeholders)** | In a step's payload, what the player replaces by a line's id, since an id is a hash nobody can write: `$line` (a labelled step's line id), `$goal` (`goal::` and that id), `$find` (the first line a check matches). A **reference** is not one: the player leaves it in the line. |
| **[reference](conditions.md#references)** | In a condition or a payload, what the thread expects under a name, read when the thread is read: `{ "$value": key }` (the value handle's key), `{ "$set": name }` (a set's members), and in a `when` only `$writer`, `$draft` and `{ "$now": "instant" }` (the instant the line is admitted at, which `post` and `dryRun` are given: the clock at the door). Only `$value` may stand in a payload. |
| **[hole](reading.md#holes)** | A reference to a value no line in force states (a value stated through a reference counts for none: only the lines that hold no reference feed resolution). Awaited, never denounced: the reading lists it, with the lines that hold it, and a condition that reads it is false until a **fill** states it. |
| **[fill](schema.md#value)** | A line that states the value a hole refers to: of a gist whose `value` rule takes its key from the payload. Later fill wins; revoking it gives back what stood before. It may not state a key a rule of the schema states. |
| **misfit** | Something a schema author wanted that the engine cannot say. Each is recorded in [misfits.md](../project/misfits.md) with what the engine does and the smallest change that would make it fit. |
| **domain** | In the playground, a case together with the application's side of it, the **UI schema**: one module in `playground/src/domains/`. The rest of the page reads the domain in use and names no gist. |
| **UI schema** | What an application needs to know about each gist beyond the schema: its words, its card, how a person composes it, how a goal awaits it. It is the application's, not the library's. |
| **[consolidation](consolidation.md)** | Two threads made one: a new thread opens by naming the two **sources**, and each is replayed into it, the first's steps and then the second's, through `post` as any line is. Never a merge: the sources' chains are not interleaved, and the new lines are new lines. |
| **[source](consolidation.md#consolidate)** | A thread that a consolidation takes from, together with the schema it is read by. It is not changed, and may be consolidated more than once. |
| **[seal](consolidation.md#consolidate)** | A source as the new thread's declaration names it: `{ first, last }`, the id of the source's first line (which thread) and of its last line in reading order, its head (where it was closed). A line written to the source after its seal is visibly after it. |
| **[derived schema](consolidation.md#deriveschema)** | The schema of a consolidated thread: the pushout of the sources'. What both share is kept once, what only one has is added; the same schema twice is itself. Otherwise it is new, named by the host at version 1. `deriveSchema` gives it. |
| **[schema conflict](consolidation.md#deriveschema)** | A part two sources' schemas state differently, found by comparing canonical forms: an `opening`, an `authority`, a record role, a guard, a gist or a law at two strengths; and, asked in the same way, a law only one source has. A person answers a conflict with the first source's part, the second's or one written by hand, and a one-sided law with keep or drop: the new thread applies one set of laws. |
| **[drill](consolidation.md#the-drill)** | A consolidation walked step by step: a value that `stepDrill` moves on by one step, and that stops at a schema conflict or at a step the new thread refuses, and waits for a choice (first, second, by hand; take it again, edit it, skip it; abort). |
